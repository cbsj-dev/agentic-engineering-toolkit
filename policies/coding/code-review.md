# Code Review Policy

## Review Focus

Review for correctness, behavioral regressions, security risks, data loss,
concurrency problems, and missing test coverage before commenting on style.

## Findings

- List findings first, ordered by severity.
- Include a file and line reference for each actionable finding.
- Explain the triggering condition and impact.
- Do not report style preferences as defects unless they violate a documented policy.
- If no findings exist, say so and identify residual testing gaps or assumptions.
